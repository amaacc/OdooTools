## 1. سيناريو ومسار عمل البرنامج (Workflow)
البرنامج يعمل في بيئة معزولة تماماً داخل المجلد [`c:\OdooDB\OdooImport\`](file:///c:/OdooDB/OdooImport/):
1. **قراءة ملف المورد (`suppItems.xlsx`):**
   - السطر الأول: بيانات المورد (الخلية B1 تحتوي على `رقم المورد Supplier No` مثل `905-315`، والخلية C1 تحتوي على `اسم المورد Supplier Name`).
   - السطر الثاني: أسماء الأعمدة بالعربي.
   - السطر الثالث: أسماء الأعمدة بالإنجليزي (`BRAND`, `ProductNameen`, `ProductNameAr`, `EA barcode `, `CS barcode`, `CS SIZE`, `CS COST (excl VAT)`, `EA COST (excl VAT)`, `Country of Origin`, `Picture`, `Shelf Life (Days)`, `TAX`, `Category`, `Sub Category`).
   - الأسطر من الرابع وما بعده: بيانات الأصناف.
2. **الاتصال والتحقق المباشر من أودو 17 (`odoo_verifier.py`):**
   - فحص الباركودات: التحقق من خلو أودو من الباركود (في `product.product.barcode` و `product.packaging.barcode`).
   - فحص التصنيفات: التأكد من وجود `Category` في جدول `product.category`.
   - فحص الوسوم: التأكد من وجود الوسم الافتراضي، البراند، ووسم المورد في `product.tag`.
   - استخراج أحدث كود تسلسلي في المدى المطلوب (`Internal Reference Sequence`).
3. **توليد ملف الإكسل المعتمد (`Odooimport.xlsx`):**
   - **الصفحة 1 (`OdooImport`):** الأعمدة الـ 16 المعتمدة للرفع المباشر إلى أودو 17 + عمود الملاحظات، مع تظليل الخلايا التي تحتوي على أخطاء باللون الأحمر الفاتح (`#FFC7CE`).
   - **الصفحة 2 (`مقارنة الأصناف المسجلة`):** جدول مقارنة تفصيلي جانبي (Side-by-Side) لكافة الأصناف التي وُجدت مسجلة مسبقاً في أودو، يوضح فروقات التكلفة، سعر البيع، والأسماء والتصنيف لمساعدة الإدارة على اتخاذ القرار.
4. **أرشفة الأصناف السليمة في الأرشيف العام (`AllNewItems.xlsx`):**
   - عند خلو الملف من الأخطاء، يتم نسخ الأصناف إلى نهاية ملف `AllNewItems.xlsx` مع تعبئة العمودين 15 و 16 برقم واسم المورد بأمان تام.

## 3. المعادلة المعتمدة لاحتساب سعر البيع والتقريب (Pricing Algorithm)

```python
def calculate_sales_price(cost: float, margin: float = 0.20, is_taxable: bool = True, tax_rate: float = 0.15) -> float:
    # 1. إذا كانت التكلفة 0 تعود 0 مباشرة
    if not cost or cost <= 0:
        return 0.0

    # 2. هامش الربح الصافي الحقيقي (True Margin)
    price_excl_vat = float(cost) / (1.0 - margin)

    # 3. احتساب ضريبة القيمة المضافة ZATCA (15%)
    raw_price = price_excl_vat * (1.0 + tax_rate if is_taxable else 1.0)

    # 4. التقريب لأقرب ربع ريال للأعلى (Nearest Upper Quarter: 0.25, 0.50, 0.75, 1.00)
    val = round(raw_price, 4)
    quarter = math.ceil(val * 4.0) / 4.0

    # 5. قاعدة الهللة: إذا كان الناتج عدداً صحيحاً موجباً ينقص هللة واحدة (مثال: 100.00 -> 99.99)
    if abs(quarter - round(quarter)) < 1e-6:
        return round(quarter - 0.01, 2)
    return round(quarter, 2)
```

### أمثلة عملية معتمدة:
* التكلفة = `40.00` $\rightarrow$ الناتج: $40 / 0.80 = 50.00 \times 1.15 = 57.50$ (ربع ريال صريح) $\rightarrow$ السعر: **`57.50`**.
* التكلفة = `32.00` $\rightarrow$ الناتج: $32 / 0.80 = 40.00 \times 1.15 = 46.00$ (عدد صحيح) $\rightarrow$ خصم هللة $\rightarrow$ السعر: **`45.99`**.
* التكلفة = `73.00` $\rightarrow$ الناتج: $73 / 0.80 = 91.25 \times 1.15 = 104.9375$ $\rightarrow$ التقريب للربع الأعلى يعطي $105.00$ (عدد صحيح) $\rightarrow$ خصم هللة $\rightarrow$ السعر: **`104.99`**.
* التكلفة = `31.00` $\rightarrow$ الناتج: $31 / 0.80 = 38.75 \times 1.15 = 44.5625$ $\rightarrow$ التقريب للربع الأعلى $\rightarrow$ السعر: **`44.75`**.

## 4. تدقيق الباركود وخوارزمية GS1 Checksum

الباركود يجب أن يتكون من 8 أو 12 أو 13 أو 14 رقماً رقمياً فقط، ويُحسب رقم التحقق بالأوزان المتناوبة (3 و 1 من اليمين لليسار بعد استبعاد رقم التحقق الأخير):
$$\text{Checksum} = \left(10 - \left(\sum \text{digits} \times \text{weights}\right) \pmod{10}\right) \pmod{10}$$
إذا لم يتطابق، تُظلل الخلية بالأحمر وتُسجل ملاحظة في عمود التدقيق.

3. `الاسم إنجليزي (أودو)` مقابل `الاسم إنجليزي (المورد)`
4. `الاسم عربي (أودو)` مقابل `الاسم عربي (المورد)`
5. `التكلفة بأودو` مقابل `التكلفة الجديدة` مع `فرق التكلفة (+/-)` ملون بالأخضر أو الأحمر
6. `سعر البيع بأودو` مقابل `السعر الجديد المقترح` مع `فرق سعر البيع (+/-)`
7. `التصنيف بأودو` مقابل `التصنيف من المورد`
8. `ملاحظات التغيير والفروقات`
